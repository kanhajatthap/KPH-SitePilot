# wp-agent — Workspace Agent Guidelines

`wp-agent` is a provider-independent AI WordPress agent monorepo designed with a security-first, read-only foundation. Mutating site-builder workflows are only enabled through explicit approval and verification gates.

## Core Operational Constraints

1. **Security & Secrets**:
   - Never write, log, or commit credentials, API keys, database passwords, or auth salts.
   - Never target or connect to production WordPress environments.
   - Restrict all local WordPress interactions to isolated LocalWP test sites (e.g., `plugin-test.local`).
   - All tool-driven WordPress execution and site modifications remain **deny-by-default**; never bypass explicit approval, scope validation, or post-action verification.

2. **Monorepo & Toolchain**:
   - Package manager: `pnpm` (Corepack-managed, v12+).
   - Monorepo orchestrator: Turborepo (`turbo`).
   - PHP runtime & tooling: LocalWP bundled PHP 8.2 (`php.exe`), Composer 2 (`composer.phar`), and WP-CLI (`wp-cli.phar`).
   - Node runtime: Node.js 22 LTS.

3. **Implementation Discipline**:
   - Read-only inspection is the default. Use only existing approval-gated mutation workflows.
   - Do not scaffold code, create plugins, or generate ZIP packages until explicitly directed.
   - Do not alter LocalWP databases or core files during environment preparation.
   - Do not apply Supabase migrations or run database tests against hosted/remote databases; use only the isolated local Supabase stack.

4. **Token Efficiency & Workflow**:
   - Load only files and skills relevant to the active task.
   - Prefer targeted grep/ast searches over reading directory trees or full repository dumps.
   - Apply progressive disclosure: consult `.agents/rules/` for detailed constraints and `.agents/skills/<name>/SKILL.md` for specific runbooks.

5. **Evidence-Based Verification**:
   - Never report tests, builds, or commands as passing without explicit execution evidence in terminal output.
   - Report executed commands, stdout/stderr, changed files, and any remaining blockers honestly.

## Completed Agent Milestones

- Recent user/assistant context is bounded and passed to agent/chat model requests; client-supplied system messages are not trusted.
- Plugin operations are approval-gated. Uninstall is explicit and verified; bulk plugin deletion is refused.
- Existing-page updates and reversible Trash are staged for approval. The active homepage is protected, and stale changes fail closed.
- Full-page redesign uses a model-generated, schema-validated section plan. Markup is generated by code, not accepted from the model.
- Chat history persists across reloads: browser storage in local mode and session-authenticated, RLS-scoped Supabase storage in SaaS mode. Persisted messages never restore actionable approval controls. The 50-conversation archive supports archive/resume, individual delete, and confirmed clear-all; local-mode browser behavior was verified.
- Page history captures a bounded snapshot before approved page updates, section edits, Trash, and restores. Local-only history supports chat listing/comparison and staged, stale-state-checked restore with a pre-restore backup and exact read-back verification.
